关于「支持热更新」

本次交付采用 onedir（文件夹）打包，这本身就为热更新（增量更新）打好了地基：
  • 增量替换可行：运行时 PyInstaller 直接从 _internal/ 读文件，更新时只替换变更的文件即可，用户无需重下整个 1.2GB。
  • 不是「自动热更新」：文件夹形态 ≠ 自动更新器。要做到「自动检测新版本→下载→原子替换→回滚」，还需额外写更新程序（属 ClickOCR 新功能，按约定归「代码开发会话」实现；本会话仅提供形态支持，未写更新器代码）。
  • Windows 文件锁红线：app 运行中会锁住 exe 与已加载的 DLL/pyd，不能在运行时覆盖自身。可行方案：①退出后由 updater 换文件；②独立 updater 进程接手替换；③双目录（app / app_next）原子切换。
  • 用户数据保护（最重要）：更新只动 _internal/ 与静态资源；根目录下的 clickocr.db / config.ini / screenshots/ / logs/ 是用户数据，绝不可被覆盖，否则库与配置丢失。
  • 字节码版本一致：补丁里的 .pyc 必须与冻结时的 Python 3.13 完全匹配，混版本会 import 崩溃。
  • 单实例：更新前须确认旧进程完全退出（否则覆盖失败）。

技术备注（打包踩坑）

沙箱 safe-delete
WorkBuddy 沙箱对所有 Python 注入 safe-delete shim，非 TEMP 目录删除强制走回收站（本机回收站不可用）→ 打包中途 OSError 中断。
绕开方式
把 --workpath / --distpath 指向系统 TEMP（C:\Users\happy\AppData\Local\Temp），删除直接放行；构建后由 bash cp -r 把产物搬回 dist/。经验已记入工作日志。
单实例互斥
ClickOCR 为单实例（INSTANCE_NAME=ClickOCR-SingleInstance），重复启动会聚焦已有窗口并退出，冒烟测试需注意先退出旧实例。
GPU 构建前置
需 .venv 安装 onnxruntime-gpu（当前 1.28.0 在位，CUDAExecutionProvider 可用）；本机须有 N 卡 + 新驱动才能真实激活 CUDA。
